---
title: CIP-113 programmable tokens
description: How programmable tokens are served, and why they need CIP-26 or CIP-68 metadata too.
---

[CIP-113](https://cips.cardano.org/cip/CIP-0113) defines **programmable tokens**: tokens whose transfers and minting are governed by on-chain scripts, for example for regulated stablecoins or tokenised securities. A token is registered in an on-chain **registry**, a sorted linked list of nodes, one per policy.

## What the registry serves

A registry node says only that a policy is programmable, and which scripts govern it. It has **no name, ticker or logo**. So a programmable token takes its ordinary metadata from [CIP-26](../cip26/) or [CIP-68](../cip68/), and the V2 response adds:

```json
{
  "type": "PROGRAMMABLE",
  "extensions": {
    "cip113": {
      "minting_logic_script": "…",
      "transfer_logic_script": "…",
      "third_party_transfer_logic_script": "…",
      "unfracking_logic_script": null,
      "global_state_policy_id": "…"
    }
  }
}
```

CIP-113 does not participate in the metadata merge or `query_priority`.

A registered policy whose tokens have no CIP-26 or CIP-68 metadata is still served under the default `validation=ALL`, with a `MANDATORY` `missing_value` error on `companion_metadata`. `MANDATORY_ONLY` and `STRICT` return `404` for that subject or omit it from a batch. The companion requirement is a rule of this metadata registry.

## Before you mint

Choose the metadata source before minting:

- For CIP-68, choose the user token's label before minting: `333` for fungible tokens or `444` for rich fungible tokens. Its metadata lives in the datum of a reference NFT with label `100`, the same policy ID and the same asset-name bytes after the label prefix. Those asset names determine the pairing; registering the policy in CIP-113 is a separate operation. Once minted, the token's asset name is fixed, so an asset with an added label would be a different token. See the [CIP-68 minting guide](../cip68/) for the exact prefixes and datum format.
- A CIP-26 entry can be added after registration, provided you retain the signing authority required for that policy. Follow the [CIP-26 registration guide](../cip26/).

## Registration tooling

To build and submit a registration, use the official [CF CIP-113 tooling](https://github.com/cardano-foundation/cip113-programmable-tokens). The metadata registry indexes registered policies and exposes their script information; it does not build or submit those transactions.
